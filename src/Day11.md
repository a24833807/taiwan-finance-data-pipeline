# Day 11 學習筆記：將交易日期改為外部執行參數

今天將 ETL Pipeline 的交易日期從程式內固定設定，改成由外部執行參數傳入，讓同一份程式可以處理不同日期的 TWSE 資料。

目前執行方式為：

```bash
python src/main.py --trade-date 20240701
```

## 1. 移除 main.py 中寫死的日期

原本交易日期直接寫在 `main.py` 中：

```python
trade_date = "20240701"
```

這會造成每次需要處理不同日期時，都必須修改程式碼。

修改後，交易日期改由執行環境傳入，使程式邏輯與執行參數分離。

## 2. 使用 `--trade-date` 傳入交易日期

Pipeline 現在可以透過命令列參數指定日期：

```bash
python src/main.py --trade-date 20240701
```

交易日期屬於每次批次執行時可能改變的輸入，因此不應該固定寫在程式碼內。

這也讓未來 Airflow 或其他排程工具，可以在執行 Pipeline 時動態傳入日期。

## 3. 在 Pipeline 啟動前檢查日期合法性

程式會先驗證傳入的交易日期，包括：

- 是否符合 `YYYYMMDD` 格式
- 月份是否合法
- 日期是否真實存在

例如，下列輸入會被擋下：

```text
2024-07-01
20241301
20240230
```

這樣可以在呼叫 TWSE API 前就發現錯誤，避免無效參數進入後續的 Extract、Transform、Validate 與 Load 流程。

這種設計屬於 Fail Fast，也就是盡早發現錯誤並停止不必要的處理。

## 4. 正常交易日可以完成完整 Pipeline

輸入正常交易日時，資料可以依序完成：

```text
TWSE API
→ Extract
→ Transform
→ Validate
→ Load
→ PostgreSQL
```

表示命令列參數已成功傳入現有 ETL 流程，而且沒有影響原本的資料轉換、驗證與寫入功能。

## 5. 非交易日可以正常完成批次

當傳入週末、國定假日或其他非交易日時，TWSE API 可能不會回傳每日股價資料。

目前 Pipeline 可以正確處理空資料，記錄對應日誌並正常結束，不會因為沒有資料而異常中斷。

這代表：

```text
沒有資料
```

與：

```text
Pipeline 執行失敗
```

是兩種不同狀態。

非交易日沒有資料通常是合理的業務情境，不一定代表系統錯誤。

## 6. 未傳入日期時使用批次執行當天日期

當執行時沒有提供 `--trade-date`：

```bash
python src/main.py
```

程式會使用批次執行當天的日期作為預設值。

相較於使用固定歷史日期，這種設計更符合每日批次作業的使用情境。

整體行為為：

```text
有傳入 --trade-date
→ 使用指定日期

沒有傳入 --trade-date
→ 使用批次執行當天日期
```

指定日期適合歷史資料回補與重新執行；執行當天日期則適合一般每日批次。

## 今日理解

今天完成的不只是加入命令列參數，而是將「交易日期」從程式內部設定，改成 Pipeline 的外部輸入。

這讓 Pipeline 具備更好的重複使用性與可排程性：

```text
執行參數
→ 日期合法性檢查
→ Extract
→ Transform
→ Validate
→ Load
```

此外，正常交易日、非交易日與錯誤日期現在都有不同且明確的處理方式，讓 Pipeline 的執行行為更加穩定。
